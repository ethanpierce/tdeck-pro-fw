# T-Deck Pro bench record — 2026-10-16

Handheld OS 0.1 was built, flashed and tested on macOS with a physical
T-Deck Pro. The original starter was flashed first, then the on-device
Settings app and network-query controls were added and tested. Device-specific
identifiers, raw serial logs, camera images and factory dumps are kept locally
and are not included in this public repository.

## Hardware and recovery

- ESP32-S3 revision v0.2; Winbond JEDEC `ef:4018`; detected flash 16 MiB.
- Firmware auto-detected board v1.1; the factory screen also identified v1.1.
  The enclosure was not opened to inspect the PCB marking.
- USB VID/PID `303a:1001`, connected directly to the Mac.
- A complete **16,777,216-byte original ESP32 flash backup** was saved before
  the first upload, with a second local copy. Every saved read passed a
  device-side MD5 check; the assembled dump also matched a device-side MD5
  of the full 16 MiB. Both copies and their manifest remain outside Git.
- Large reads with newer esptool stubs stalled; JTAG reads reported CRC errors.
  Successful recovery used verified 4 KiB reads with esptool 5.3.1 and 4.5.1.
  These workarounds were needed for backup, not normal firmware uploads.

result does not establish universal coverage or carrier eligibility.

## Full SIM storage follow-up

The SM count above is **5 used out of 5 total**, while ME was **0 out of 180**.
The earlier all-SM receive preference could therefore block further incoming
messages. This is a plausible cause for the missing reply, not proof that a reply
reached the network or that changing storage alone resolves inbound service.
All carrier welcome messages remain preserved.

The software now prefers `CPMS="SM","SM","ME"` and falls back to all-SM when
the modem rejects ME reception. It imports both stores at startup and on an
inbox request, handles SM and ME notifications, restores the SIM read store
after each ME scan, and retries failed UI delivery without deleting messages or
resubmitting SMS. Automatic scans do not dump raw PDUs. A full receiving store
reported during setup produces a warning; ME may eventually fill too.

This storage change is prepared for the next build; hardware CPMS confirmation
and a new incoming-message check remain pending. Host simulations cover a full
SIM with ME reception, preserved unsupported carrier messages, dual-store
import/deduplication, fallback/full-store warning, a 100-message ME stream with
interleaved notifications, restoration/timeouts and queue-backpressure retry.
Windows hardware flashing remains untested.

Wi-Fi and NimBLE, a native e-paper/canvas driver, and RadioLib's portable C++ HAL.
The original flash layout and NVS blob formats are preserved; no settings erase
was performed. A private local NVS backup was made before migration.

The native host pass includes eleven sanitized binaries and 30 modem/UART
scenarios, including strict TCP-mode queries and repeated NETOPEN reuse. The
production build enables `-O2`, retaining assertions, watchdogs, TLS verification,
stack sizes and task affinity. The UI runs on CPU1 and cellular/AI/BLE workers on CPU0.
Application image: 1,413,472 bytes; SHA-256:
`2a45c4215079ea0b98a3cd685817ea48fc5e7dc4b574cc3382513174e9feb550`.
Static RAM: 52,488 bytes. All four ROM-loader upload hashes verified.

## BOOT hold shutdown and Settings power off

The user resumed development specifically for BOOT-hold shutdown: clean at
5 seconds, forced at 30 seconds, RESET to start. A debounced independent core-0
monitor uses a 4,096-byte task stack. The same clean flow is available through
Settings confirmation and USB `power off`. It displays Shutting down during
cleanup, then Powered off with RESET instructions. Saved radio/Airplane and
credential settings are not changed. No message/call was sent for this check.

The v1.1 schematic was inspected: BOOT is GPIO0, RESET resets the SoC, and the
BQ25896 QON pin is not connected to those buttons. A true battery-isolation
shutdown cannot preserve RESET wake on this board. Both implemented paths
therefore use external-radio rail shutdown plus ESP32 deep sleep; the 30-second
path bypasses the UI and bus/storage locks. It is not an independent hardware
power switch or a failsafe against all MCU hangs. Off-state current remains
unmeasured.

A private 20 KiB NVS backup was saved without examining its credentials. The
first shutdown build (1,458,720 bytes, image SHA-256
`bcf2c0112a215ea7d9439ac1942b032c2af0b659b342f06154603037ad868d0f`)
was flashed through the ROM loader; all four image hashes verified. Native boot,
CST3530 touch/keyboard readiness, NVS message storage, saved hidden key presence,
lights/APN and saved Wi-Fi OFF/BLE OFF were confirmed. LTE registered before the
shutdown test. No request to an AI provider or new SMS/call was made.

The monitor had 3,404 bytes of free stack. Internal heap was 182,139 bytes free,
181,799 minimum; PSRAM free was 8,376,528 bytes before the shutdown. Battery read
was unavailable on that boot; battery-only operation is not established.

The explicit USB power-off command at 39.143 seconds completed cleanup at
41.370 seconds. Cellular power-off and final completion were logged, then the
native USB port disappeared. This is a hardware check of the clean shutdown
path with USB attached. It does not independently measure RF silence/current,
physical BOOT timing, battery-only shutdown or RESET wake. The BRIO was not
connected, so the new screen sequence is not camera-confirmed.

An added native-panel shutdown test then exposed an existing state-cache issue:
post-frame panel-setting initialization cleared a power flag, causing the old
powerOff guard to skip an explicit panel-off command. The driver now tracks
confirmed-off separately; the regression verifies that shutdown sends the
command and that repeated shutdown stays idempotent. The corrected native build
is 1,458,752 application bytes with 55,224 bytes of static RAM, SHA-256
`2fc73c4132515140b7c732dccd371007896df0728ff1b7d6307e4ef49fa93258`.
The user then confirmed both physical tests on the first shutdown image:
RESET to start, BOOT held for 5 seconds and released, Shutting down followed by
Powered off, RESET to start, a continuous 30-second BOOT hold, release and RESET
to start again. This is user-observed functional acceptance, not an instrumented
measurement of button timing or off-state current.

After the user's RESET/reconnection, the corrected image above was flashed;
all four flash hashes verified. Native boot, CST3530 readiness, message storage,
saved hidden key presence, APN/lights and Wi-Fi OFF/BLE OFF were checked. Its
monitor had 3,404 bytes of free stack; internal heap was 182,379 bytes free,
182,283 minimum, and PSRAM free was 8,376,528 bytes. The battery reading was
still unavailable. Modem startup was checking/reconnecting before shutdown;
LTE registration was not retested on this final image.

On the final image, USB `power off` at 10.409 seconds completed cleanup at
12.635 seconds; the radio-off line followed at 12.645 seconds. Native USB then
disconnected as expected and a read-only enumeration confirmed it absent. The
device was left asleep with no console/server or agent running. No new SMS,
call, AI request, GPS enable or Mesh transmission was initiated for these tests.

The host runner includes 18 sanitized binaries. Shutdown checks include exact
